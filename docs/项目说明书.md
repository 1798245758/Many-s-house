## 1. 项目概述

本项目是一个 **RAG（检索增强生成）个人知识库系统**，单用户本地部署。

用户上传 **PDF / TXT / Markdown / XMind / Word / Excel / PowerPoint / 图片** 等文件，系统自动完成「解析 → 清洗 → 语义切块 → 向量化 → 索引构建」的离线链路；在用户提问时，系统执行「问题向量化 → 混合检索（向量相似度 + FTS5 关键词）→ 上下文拼接 → DeepSeek LLM 生成回答」的在线链路，并附带引用来源（sources）。

当前最终形态：

- **向量化**：使用国内开源 BGE 模型 `BAAI/bge-base-zh-v1.5`（768 维），通过 `sentence-transformers` 本地推理，配置了 HuggingFace 国内镜像 `hf-mirror.com` 与模型加载超时机制；模型不可用时回退到 MD5 伪向量化。
- **文档解析**：基于 LangChain `DocumentLoaderManager` 统一管理多源 Loader，提取内容、元数据、结构信息。
- **切块策略**：语义切块，每块约 **500~1000 Token**，边界重叠 **100 Token**，防止语义割裂丢失。
- **LLM**：DeepSeek API（Chat）。

## 2. 项目背景与目标

### 2.1 背景

- 初始为「从零构建一个 RAG 知识库」的学习与实践项目，采用 **Vibe Coding** 方式，通过与 AI Agent（OpenCode）多轮对话迭代完成。
- 开发过程中用户提出大量增强与修复诉求（多文件上传、图片上传、文档替换、翻页搜索、自动启动、XMind 支持、真实向量化、多格式解析等），均沉淀为本说明书的 Prompt 提示词章节。

### 2.2 目标

1. 个人文档知识库：上传 → 索引 → 智能问答，带引用来源。
2. 支持中文场景为主（BGE 中文模型、微软雅黑字体、中文错误提示）。
3. 本地化、轻量、可离线演示：SQLite 单库、本地模型推理、前后端分离。
4. 低维护成本：`npm run dev` 一键同时启动前后端。

## 5. 功能模块清单

| 模块 | 页面/路由 | 功能 |
|------|-----------|------|
| 主页 | `/` (Home) | 欢迎信息 + 快速入口（上传文档 / 开始提问） |
| 对话 | `/chat` | 输入问题 → 展示 AI 回答 + 引用来源；加载/空/错误态 |
| 文档管理 | `/documents` | 多文件上传、列表（分页 + 搜索）、删除、替换/覆盖更新（PUT）、图片上传 |
| 历史记录 | `/history` | 查询历史列表，每条可「重新提问」并跳转聊天页预填问题 |
| 个人信息 | `/profile` | 昵称/邮箱编辑、DeepSeek API Key 配置、主题切换（亮/暗） |
| 关于数据 | `/about` | 数据来源说明、隐私声明、使用条款 |

### 关键交互细节（开发中沉淀的约束）

- **上传**：支持一次多文件；文本类文档无需 API Key，仅图片需要 DeepSeek Vision 描述（该能力后续已被移除，图片仅保存占位文本）；错误时展示后端真实错误信息而非笼统「上传失败」。
- **文档列表**：随文档增多需分页 + 文件名搜索，便于定向删除。
- **历史「重新提问」**：从历史点击后跳转 `/chat` 并预填问题。
- **字体**：提问/回答字体以贴近 DeepSeek 提问框的观感为准（最终采用 system-ui 字体栈，保证可读性、抗锯齿、行高）。
- **启动**：前端打开时后端应自动启动（concurrently + wait-on `tcp:127.0.0.1:8000`）。

## 6. 数据库设计

表结构（SQLite，见 `app/models/`）：

```sql
-- 文档表
documents (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    filename      TEXT NOT NULL,          -- 原始文件名
    file_type     TEXT NOT NULL,          -- pdf/txt/md/xmind/docx/xlsx/pptx/png/...
    file_size     INTEGER,                -- 字节数
    chunk_count   INTEGER DEFAULT 0,
    status        TEXT DEFAULT 'pending', -- pending/processing/ready/error
    metadata_json TEXT,                   -- 解析出的元数据 JSON
    structure_json TEXT,                  -- 文档结构 JSON（标题/章节/工作表/幻灯片等）
    created_at    TEXT DEFAULT (datetime('now'))
);

-- 文本块表
chunks (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    document_id  INTEGER NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index  INTEGER NOT NULL,
    content      TEXT NOT NULL,
    token_count  INTEGER,
    embedding    BLOB,                    -- 768 维 float32（struct 序列化）
    metadata_json TEXT,
    created_at   TEXT DEFAULT (datetime('now'))
);

-- FTS5 全文索引虚拟表（content 外置关联 chunks）
CREATE VIRTUAL TABLE chunks_fts USING fts5(content, content='chunks', content_rowid='id');

-- 查询历史
query_history (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    query_text  TEXT NOT NULL,
    answer_text TEXT NOT NULL,
    sources     TEXT,                     -- JSON：来源 chunk 信息
    created_at  TEXT DEFAULT (datetime('now'))
);

-- 用户（单用户模式）
users (id, nickname DEFAULT '用户', email, avatar);

-- 设置（Key-Value）
settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
-- 预置 key：api_key（DeepSeek API Key）、theme（light/dark）
```

## 8. 核心流程

### 8.1 离线链路（上传 → 索引就绪）

```
用户上传文件（可多个）
  → 保存到 uploads/，写入 documents 表（status=pending→processing）
  → DocumentLoaderManager 按后缀选择 Loader 提取 content/metadata/structure
    （图片文件：仅保存占位文本）
  → cleaner 清洗（去零宽字符/多余空行/行首尾空白）
  → semantic_chunk：按句子边界切块，500~1000 Token，重叠 100 Token
  → embedder → embedding.embed_text_list（BGE 768 维，带 lru_cache）
  → indexer.save_chunks：写 chunks 表 + 重建 FTS5 索引
  → documents.status = ready
```

### 8.2 在线链路（提问 → 回答）

```
用户输入 Query
  → embed_query（BGE 向量化）
  → hybrid_search：向量检索（余弦相似度）+ FTS5 关键词检索（空结果回退 Python 子串匹配），融合去重排序 Top-K=10
  → 无结果 → 返回「当前知识库中没有相关信息，请先上传文档。」
  → 拼接上下文 context（Top-K chunk content）
  → DeepSeek Chat 生成回答（system：仅基于上下文回答，无信息时诚实说明）
  → 写入 query_history，返回 { answer, sources(前3条, 每条含 chunk_id/content 前200字/文档名) }
```

## 11. 迁移到 QderCN 注意事项

1. **交接内容**：将本说明书 + `docs/` 下设计/计划文档作为 QderCN 的项目上下文（System/项目说明）导入，重点保留第 10 节 Prompt 提示词，帮助新 Agent 复现「需求 — 决策 — 实现」脉络。
2. **环境依赖**：
   - 后端：Python 3.10+；`pip install -r backend/requirements.txt`（建议清华源）。
   - BGE 模型约 400MB，首次启动自动下载；已内置 `HF_ENDPOINT=https://hf-mirror.com` 国内镜像；超时可调 `BGE_MODEL_TIMEOUT`（默认 120s）。
   - 前端：`npm install`（建议 npmmirror 镜像）；Node 需支持 Vite 5。
3. **启动方式**：`cd frontend && npm run dev` 一键同启后端（uvicorn :8000）+ 前端（vite :5173）。注意 QderCN 环境下 `concurrently` 与 `wait-on` 的可用性，必要时拆分为 `npm run dev:backend` / `dev:frontend` 两条命令。
4. **模型与 LLM 配置**：`backend/.env`（参照 `.env.example`）配置 `USE_BGE_MODEL`、`BGE_MODEL_NAME`、`BGE_MODEL_TIMEOUT`；DeepSeek API Key 在页面「个人信息」中配置并持久化到 settings 表。
5. **数据迁移**：知识库数据在 `backend/data/knowledge.db`，上传文件在 `backend/uploads/`，迁移时需一并携带；数据库结构变更需重建 FTS5 索引（`chunks_fts` 在 indexer 中自动 rebuild）。
6. **后续扩展方向（对话中反复探讨但尚未落地）**：
   - Query Rewriting（`rewriter.py` 计划已写好，未实现）。
   - Function Calling 定制化封装（针对项目场景的小型工具调用）。
   - 真正向量数据库（当前为 SQLite + 全表余弦计算，可替换为 MCP/独立向量库）。
